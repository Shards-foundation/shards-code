# Publication scope

Shards Code is an independent fork maintained by Shards Foundation. It is not affiliated with, endorsed by, or an official product of MiniMax. The local rebrand is based on the public MiniMax Code source revision recorded in [Source status](open-source-status.md).

The planned destination is `Shards-foundation/shards-code`, but this local work does not create or publish that repository. No GitHub credentials have been used; no repository creation, push, release, or other public write has occurred. Publication is owner-gated: the owner must inspect the exact final diff, local commit, and final test/scan report and explicitly approve the public write. The intended history treatment for the new destination must be reviewed with that same package.

## Included material

The reviewed source inventory covers the terminal UI, headless CLI, ACP server, build and release scripts, tests, prompts, agents, skills, templates, examples and documentation. The Shards Code name and original Shards-created product identity are used for current user-facing product surfaces.

The legally required original MiniMax copyright and MIT attribution remain unchanged in `LICENSE` and `NOTICE`. Factual MiniMax provider, model-catalog and API compatibility references remain where needed for functionality. The pinned `mcode-tools` artifact and other third-party code/assets keep their original identity and all applicable notices. See [License status](../LICENSE-STATUS.md) and [Third-party notices](../THIRD_PARTY_NOTICES.md).

## Excluded material and claims

Do not publish account data, logs, sessions, credentials, private review material, or material whose license/provenance is not established. Do not claim MiniMax affiliation, endorsement, product ownership, account support, or MiniMax release availability. Upstream verification, demos and live-service records are not Shards evidence. No Shards installer, npm package or release archive is available from this source snapshot.

## Release review

Before any public source, archive, npm package or release publication, review the exact commit and diff; run the required verification gates and report exact pass/fail/skip counts; run current source, history and built-artifact secret scans; confirm license texts, package identities and attribution; and record known limitations and test scope. Preserve `LICENSE`, `NOTICE`, third-party notices and package-level exceptions. See [Maintainers](maintainers.md), [Releasing](releasing.md) and [Verification records](verification.md).
